1. Executive Summary (For Business & PM) 
What problem this solves 
Inbound inquiries arrive through multiple channels and get handled inconsistently. This 
causes: 
●​ Missed or late follow-ups 
●​ Duplicate leads/contacts 
●​ Manual staging and inconsistent pipeline reporting 
●​ Limited visibility on lead source effectiveness 
Business value 
●​ One unified inbound pipeline: every inbound channel produces a consistent “Lead 
Event” 
●​ Fewer duplicates through automated matching rules 
●​ Faster and more accurate staging through AI-assisted classification 
●​ Cleaner reporting (source → stage → outcome) because every inbound event is 
standardized and logged 
Expected impact 
●​ Reduced manual data entry (leads created/updated automatically) 
●​ Reduced time from inquiry to correct stage placement 
●​ Improved stage consistency across teams 
●​ Higher conversion due to faster triage and follow-up 
Why this is important now 
This is foundational for scaling inbound volume without scaling headcount linearly. It 
enables reliable pipeline reporting and prevents operational breakdown as marketing and 
inbound traffic increase. 
2. User Experience Overview (For UI/UX) 
UX Principle: “Tracking Only” 
This feature does not add a chat inbox or store full message threads.​
Instead, it stores Lead Events (summarized activity + AI signals) that attach to the Lead 
timeline.

2.3 Workflow Steps (Simple Flow) 
1.​ Inbound event arrives from channel 
2.​ System matches/creates Contact 
3.​ System matches/creates Lead 
4.​ System logs Lead Event 
5.​ AI classifies → suggests stage 
6.​ User accepts or overrides 
7.​ Timeline logs all actions for audit 
3. Functional Requirements (Clear & Simple) 
A. Facebook Lead Ads 
Plain language requirements 
●​ When a Facebook Lead Ad submission is received, the system must: 
○​ Create or update the Contact 
○​ Create or update the Lead 
○​ Record a Lead Event with source = “Facebook Lead Ads” 
○​ Trigger AI classification 
○​ Apply stage suggestion rules 
Duplicate handling (Contact + Lead) 
Match priority: 
1.​ Email 
2.​ Phone (normalized) 
3.​ External lead reference ID (for event idempotency only) 
Rules: 
●​ If match found: update missing fields (default) 
●​ Always log a new Lead Event per submission 
●​ Never create duplicate contacts for same email/phone (unless forced) 
Field mapping 
Admin-configurable mapping: 
●​ Facebook form fields → CRM lead/contact fields 
●​ Support custom fields 
●​ Support “default values” when field is missing 
Technical notes 
●​ Use Meta Graph API + Lead Ads Webhooks 
●​ Must implement: 
○​ Webhook signature verification 
○​ Idempotency (same lead submission should not create duplicates) 
○​ Retry-safe processing 
B. Facebook Messenger (Lead Tracking Only) 
Plain language requirements 
●​ When an inbound Messenger message arrives: 
○​ Create a Messenger Lead Event (not a conversation record) 
○​ Match/create Contact 
○​ Match/create Lead 
○​ Trigger AI classification 
○​ Log activity entry in lead timeline 
Event grouping rules (tracking only) 
●​ Do not store threads. 
●​ Optionally group multiple events into a single “Recent Messenger Activity” rollup 
(UI-level grouping), but storage remains event-based. 
Contact identification 
Primary identifier: 
●​ Page-scoped user identifier (PSID) + Page ID (external reference) 
If the lead later submits a form with email/phone: 
●​ Link PSID to the matching contact via verified match rules. 
Technical notes 
●​ Use Messenger inbound webhooks 
●​ Store minimal payload: 
○​ Channel, timestamp, external IDs 
○​ Optional sanitized snippet (default OFF) 
○​ AI extracted signals 
C. WhatsApp Business API (Lead Tracking Only) 
Plain language requirements 
●​ When an inbound WhatsApp message arrives: 
○​ Create a WhatsApp Lead Event 
○​ Match contact by phone (E.164) 
○​ Match/create lead 
○​ Trigger AI classification 
○​ Log activity in lead timeline 
Media support (tracking only) 
●​ Do not store media files by default. 
●​ Store only: 
○​ has_media = true/false 
○​ media_type (image/document/audio) 
○​ optional external media reference ID (for audit/troubleshooting) 
Contact matching rules 
Primary: 
●​ Phone number normalized to E.164 
Conflict handling (same phone on multiple contacts): 
●​ Attach to the most recently active lead/contact 
●​ Flag a “Data conflict” warning in logs for cleanup 
Technical notes 
●​ Use WhatsApp Cloud API webhooks 
●​ Validate webhook token/signature 
●​ Normalize phone numbers consistently 
D. WordPress Plugin (Custom) 
Plain language requirements 
●​ WordPress forms send leads into CRM securely and reliably. 
●​ The plugin must: 
○​ Authenticate using an API key 
○​ Push form data via HTTPS 
○​ Retry transient failures 
○​ Queue locally if CRM is unreachable 
Secure connection 
●​ CRM generates API key 
●​ WP admin configures key in plugin settings 
●​ Requests must be rejected if: 
○​ key invalid 
○​ domain restriction mismatch (if enabled) 
○​ rate limit exceeded 
Form submission behavior 
Baseline modes: 
●​ Plugin provides its own form block/shortcode; OR 
●​ Plugin hooks into popular form plugins (optional extension) 
Error handling 
●​ Retry up to N times (default 3) 
●​ If still failing: 
○​ store locally as “Pending Sync” 
○​ allow manual resend + automatic scheduled resend 
Technical notes 
●​ Endpoint: POST /api/inbound/wordpress/leads 
●​ Every submission includes: 
○​ submission_id (UUID) for idempotency 
○​ timestamp 
○​ form_id/form_name 
○​ payload 
4. AI Conversation Analysis (Explained Clearly) 
Simple explanation 
AI does not analyze “full conversation history.”​
AI analyzes the latest inbound lead signal and structured data such as: 
●​ Form fields (Lead Ads / WordPress) 
●​ The latest message text (if snippet capture is enabled) OR keyword extraction results 
●​ Channel metadata (source, time, presence of media) 
Signals AI looks for 
●​ Intent: pricing, booking, product inquiry, partnership, support, complaint 
●​ Urgency: “now”, “today”, “ASAP”, deadlines, time windows 
●​ Budget sensitivity: “how much”, “discount”, “cheapest”, “budget” 
●​ Fit indicators: location, category match, requirements 
●​ Commitment cues: “schedule a call”, “send proposal”, “ready to proceed” 
How AI decides pipeline stage 
AI outputs: 
●​ suggested_stage_label (internal AI label) 
●​ confidence_score (0–100) 
●​ reasons/signals (human-readable bullets) 
Then system maps the AI label to a real CRM pipeline stage via admin settings. 
What confidence score means 
●​ A numeric estimate of certainty. 
●​ Used to: 
○​ show suggestions more prominently when high 
○​ optionally auto-apply stage when above threshold 
When re-analysis happens 
●​ On every new Lead Event arrival 
●​ On new form submission 
●​ Optional manual action: “Re-analyze” 
Technical explanation 
●​ Asynchronous processing (does not block lead ingestion) 
●​ Message/event queue for AI jobs 
●​ Triggers: 
○​ inbound_event_created 
○​ lead_updated (after mapping) 
●​ Debounce rule: 
○​ if multiple events arrive quickly, analyze once after short delay (configurable)

5.2 Inbound Endpoints 
●​ POST /webhooks/facebook/lead-ads 
●​ POST /webhooks/facebook/messenger 
●​ POST /webhooks/whatsapp/messages 
●​ POST /api/inbound/wordpress/leads 
Minimum requirements: 
●​ Auth verification (signature/token/api key) 
●​ Schema validation 
●​ Idempotency handling 
●​ Error classification (4xx vs 5xx) to allow safe retries 
5.3 Processing Steps (End-to-End) 
1.​ Receive inbound payload 
2.​ Validate (signature/token/schema) 
3.​ Sanitize + store minimal lead_event 
4.​ Match contact (email/phone/PSID/WA phone) 
5.​ Create/update lead 
6.​ Write timeline entry “Inbound lead event received” 
7.​ Enqueue AI classification job 
8.​ Store AI result + timeline entry 
9.​ If auto-apply enabled and confidence ≥ threshold → update stage + log “Stage 
auto-updated” 
5.4 Security Validation 
●​ Webhook signature checks (Meta) 
●​ API key management (WordPress) 
●​ Rate limiting per endpoint 
●​ Payload minimization (do not store full message dumps unless explicitly enabled) 
5.5 Error Handling 
●​ Retry-safe ingestion (idempotency keys) 
●​ Dead-letter queue for failed AI jobs 
●​ Integration logs viewable by admins only 
●​ Alerts/monitoring for: 
○​ high webhook failures 
○​ no inbound events received for X hours 
○​ queue backlog growth

9. Risks & Dependencies 
API dependency risks 
●​ Meta API outages, throttling, schema changes 
●​ Webhook delivery delays/retries 
Policy limitations 
●​ WhatsApp Business verification and compliance requirements 
●​ Facebook platform policy changes affecting data access 
AI accuracy risks 
●​ Misclassification causing wrong stage routing if auto-apply is too aggressive 
●​ Requires threshold tuning and monitoring 
Data privacy risks 
●​ Inbound messages may contain sensitive personal data 
●​ Mitigation: minimal storage, snippet OFF, retention controls, access control
